# 구형 한국어 시스템 문체 규격 (1995~2005)

이 문서는 **프로그램에 표시되는 한국어 UI 문구**에 적용한다. Codex가 사용자에게 답변하는 대화체까지 변경하는 규칙이 아니다. 목표는 1995~2005년 운영체제 번역문, 설치 마법사, 국산 유틸리티, 업무용 웹 시스템에서 볼 법한 공식적·절차적·기술적인 표현이다.

## 핵심 원칙

1. **컴퓨터는 명령을 수행하고 상태를 보고한다.** 사용자에게 말을 걸거나 감정을 표현하지 않는다.
2. 종결형은 문맥에 따라 `~합니다`, `~되었습니다`, `~하십시오`, `~하시겠습니까?`, `~할 수 없습니다`를 사용한다. 모든 문장을 억지로 장문으로 만들지 않는다.
3. 메시지 구조는 가급적 **대상 → 동작/결과 → 조치**의 순서로 작성한다. 예: `서버에 연결할 수 없습니다. 네트워크 연결 상태를 확인한 후 다시 시도하십시오.`
4. 감탄사, 이모지, 의인화, 축하, 동기부여, 과도한 친절, 대화형 질문을 사용하지 않는다.
5. 기술적 사실은 반드시 확인한다. 원인을 알 수 없을 때 추측하지 않는다. 진짜 오류 코드, 날짜, 진행률, 버전, 서버 주소만 표시한다.
6. 긴 설명보다 **짧고 단호한 상태문**을 우선하되, 사용자가 조치할 방법은 알려 준다.
7. UI의 언어가 영어라면 한국어 문장을 직역하지 않는다. 영어에서도 간결한 명령·상태·오류 보고 방식만 유지한다.

용어는 시대감보다 **정확한 기능과 제품 문맥**에 맞게 결정한다. 단어만 기계적으로 일괄 치환하지 않는다.

## 메시지 형식 예시

### 상태 표시줄 — 짧은 형태

```text
준비
원격 호스트에 연결하는 중...
자료를 읽는 중...
선택한 항목: 3개
처리 완료
연결 끊김
```

### 입력 검증

```text
사용자 ID를 입력하십시오.
암호를 입력하십시오.
지정한 경로가 올바르지 않습니다.
필수 항목을 모두 입력하십시오.
```

### 확인 대화상자

```text
제목: 삭제 확인
내용: 선택한 3개 항목을 삭제하시겠습니까?
단추: [예] [아니요]
```

### 연결 실패 — 아는 사실만 표시

```text
제목: 통신 오류
내용: 원격 서버에 연결할 수 없습니다.
      네트워크 연결 상태를 확인한 후 다시 시도하십시오.
단추: [다시 시도] [취소]
```

에러 번호나 특정 원인은 실제로 확인됐을 때만 추가한다. 인증 오류는 존재하지 않는 사용자와 잘못된 암호를 불필요하게 구분하여 계정 존재 여부를 노출하지 않는 등 **현대 보안 지침을 우선**한다.

## 웹 UI에 자주 쓰는 짧은 레이블

```text
사용자 ID / 암호 / 접속 구분 / 로그인
이용 안내 / 공지사항 / 회원 정보 / 사용자 관리
자료 조회 / 조회 결과 / 신규 등록 / 수정 / 삭제
저장 / 적용 / 확인 / 취소 / 초기화 / 새로 고침
시스템 상태 / 작업 이력 / 접속 기록 / 환경 설정
```

`파일(F)` 또는 `[확인(O)]` 같은 가속키 표시, 도움말 단추, 상세 오류 링크는 실제 기능이 구현되었을 때만 출력한다.

## 한국어 문체 품질 검사

- 프로그램이 사용자에게 말을 거는 듯한 문장이 남지 않았는가?
- 안내는 무조건 길게 쓰지 않고, 동작과 조치를 명확히 전달하는가?
- 단어가 당시 스타일을 연상시키되 의미를 왜곡하지 않는가?
- 가상의 오류 코드·날짜·처리량·연결 상태를 사실처럼 표시하지 않는가?
- 문체가 UI 전체에서 일관되며, 웹과 데스크톱의 실제 조작 방식에 맞는가?
